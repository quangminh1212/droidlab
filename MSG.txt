feat(protocol): implement the DLWP/1 frame header codec

Adds the fixed 24-byte header type, its reader/writer, the flag definitions from
RFC-0001 section 3.1, and the frame-level validator that maps each structural
defect to the error code and severity section 6 mandates.

Three decisions worth recording, because they are the ones a reviewer would
otherwise have to reverse-engineer:

  * Decoding never throws for malformed input. A malformed frame is an expected
    network event, and the RFC requires a specific error code and severity for
    each class. Throwing would push that mapping into catch blocks and lose the
    distinction between "different protocol version" and "broken peer", which
    have different error codes and different severities.

  * Decoding does not enforce protocol policy. Whether header_length must be 24,
    whether a message type is known, and whether a frame is too large all depend
    on a version and a negotiated limit, so they live in FrameValidator where
    they are testable against the registry instead of scattered through the
    decoder.

  * Reserved flag bits 4-7 are preserved on decode but masked off on encode.
    Section 3.1 says a receiver ignores them and a sender must leave them clear.
    Preserving them lets a receiver see an unclean peer; masking them means a
    caller cannot accidentally emit a frame a conformant peer would reject.

The magic is checked before any other field. Reading a version or a channel id
out of bytes that are not a DLWP/1 frame is exactly how a stray HTTP request or
an mDNS reply gets parsed into plausible-looking nonsense.

A bad magic is classified as ERR_MALFORMED with closing semantics. It cannot be
reported to the peer, because there is no DLWP/1 session to report it inside.

Verification: 45 tests pass. They are driven by
protocol/vectors/framing-basic.json through a loader that fails loudly when the
vectors are absent, so the suite cannot pass by discovering nothing. Round-trip
tests re-encode each vector's decoded header and require the exact original
bytes, which catches a field written at the wrong offset.
